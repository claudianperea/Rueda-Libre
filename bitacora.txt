|---|---|---|

## 6. Fase 1: Rutas y navegación

### 6.1 Anatomía de la URL de prueba

```
http://127.0.0.1:3000/Rueda-Libre/index.html
```

| Parte | Valor |
|---|---|
| Protocolo | `http` |
| Host | `127.0.0.1` (equipo local) |
| Puerto | `3000` |
| Ruta | `Rueda-Libre/index.html` |
| Método | `GET` |
| Estado | `200 OK` |

**Prueba de ruta inexistente:** se solicitó `promociones.html`, que no existe. El servidor respondió `404 – File not found`, lo que confirma que el servidor distingue entre recursos existentes y no existentes.

### 6.2 Tabla de rutas usadas (Mini reto 4)

Resume las 9 combinaciones de navegación entre las tres páginas y la ruta escrita en cada `href`.

| Archivo de origen | Destino | Ruta escrita (`href`) |
|---|---|---|

## 7. Fase 2: Estructura semántica HTML5

### 7.1 Esquema de regiones

- **`<header>`**: nombre del negocio y navegación principal (`<nav>`).
- **`<main>`**: contenedor único del contenido central de cada página.
  - *Inicio:* `<section>` de bienvenida; `<section>` de servicios con `<article>`; sección de llamada a la acción ("Reservar ahora").
  - *Tarifas y rutas:* `<section>` de tarifas con tabla; `<section>` de recorridos con tabla y botón de reserva; `<aside>` con información importante y qué llevar.
  - *Reservas:* `<form>` con tres `<fieldset>`; `<section>` de contacto; `<aside>` con horario en `<dl>`.
- **`<footer>`**: nombre del negocio, enlace `mailto:` y año de copyright.

### 7.2 Esquema visual

```
+-----------------------------------------------------------------------+
| HEADER                                                                |
|  - Nombre del negocio (<h1>)                                          |
|  - NAV: menú <ul>/<li>/<a>                                            |
+-----------------------------------------------------------------------+
| MAIN (único por página)                                               |
|  [Inicio]    SECTION bienvenida · SECTION servicios (ARTICLE) · ...   |
|  [Tarifas]   SECTION tarifas + tabla · SECTION recorridos + tabla     |
|              ASIDE (qué llevar e información importante)              |
|  [Reservas]  FORM (fieldsets) · SECTION contacto · ASIDE horario      |
+-----------------------------------------------------------------------+
| FOOTER                                                                |
|  - Nombre, correo mailto y © 2026                                     |
+-----------------------------------------------------------------------+
```

### 7.3 Justificación

- Se reemplazaron etiquetas genéricas por elementos semánticos (`header`, `nav`, `main`, `section`, `article`, `aside`, `footer`) para dar significado a buscadores y lectores de pantalla.
- Se mantuvo la jerarquía de encabezados (`h1`, `h2`, `h3`).
- **Uso de `div`/`span`:** se conservaron únicamente `<div>` de apoyo en la cabecera y en el recuadro `.note` de "Qué llevar". No se usó `span`.

## 8. Fase 3: Formulario de reservas

| Campo | Control elegido | Por qué |
|---|---|---|
| Correo | `type="email"` | El navegador valida el formato de la dirección |
| Tipo de bicicleta | `<select>` | El cliente elige una opción entre varias y se evitan respuestas escritas de formas distintas |
| Plan (horas, días, semanas) | `type="radio"` | Solo se puede elegir una opción |
| Aceptar condiciones | `type="checkbox"` | Decisión que se marca o desmarca |
| Comentarios | `<textarea>` | Permite un mensaje más largo (máx. 300 caracteres) |
| Fecha de recogida | `type="date"` | Selector nativo, limitado entre 2026-11-01 y 2026-12-31 |
| Celular | `type="tel"` con `pattern="3[0-9]*"` | Los celulares en Colombia empiezan por 3 |

Los campos se agruparon en tres `<fieldset>` con `<legend>`: **Tus datos**, **Tu alquiler** y **Confirmación**.

### 9.2 Organización de `css/styles.css`

La hoja está dividida en nueve bloques comentados:

| # | Bloque | Contenido |
|---|---|---|
| 1 | Variables de marca | Colores, fuentes y escala de espaciado en `:root` |
| 2 | Base, herencia y modelo de caja | `box-sizing`, estilos de `body`, títulos, imágenes, `main` |
| 3 | Encabezado y navegación | Cabecera azul, menú con `flexbox`, estados `hover` y `focus-visible` |
| 4 | Enlaces y botones | Estilo unificado para todos los botones del sitio |
| 5 | Portada y tarjetas | Grid de servicios, bloques de contenido |
| 6 | Tablas | Encabezado azul, bordes, filas |
| 7 | Formulario | Campos, `fieldset`, estados de foco |
| 8 | Pie de página y WhatsApp fijo | Footer y botón flotante |
| 9 | Ajustes para pantallas pequeñas | `@media (max-width: 40rem)` |

### 9.3 Decisiones técnicas

1. **Variables CSS (`--verde-ruta`, `--espacio-md`, etc.)**: cambiar un color o espacio en un solo lugar lo actualiza en todo el sitio.
2. **`box-sizing: border-box` global**: el ancho de un elemento incluye su padding y borde, lo que hace los cálculos de maquetación predecibles.
3. **Herencia**: `font-family`, `color` y `line-height` se definen en `body` y los demás elementos los heredan; solo los títulos sobrescriben la fuente.
4. **Tipografía**: Montserrat para títulos y Open Sans para texto, ambas con Arial como respaldo. Los tamaños de `h1` y `h2` usan `clamp()` para que escalen según el ancho de pantalla.
5. **Unidades relativas** (`rem`, `%`, `min()`): el ancho de `main` es `min(100% - 2rem, 68rem)`, así que se adapta sin saltos bruscos.
6. **Layout**: `flexbox` para el menú y `grid` con `auto-fit` para tarjetas de servicios.
7. **Accesibilidad**: `:focus-visible` con contorno naranja de 3 px para navegación con teclado; contraste alto entre Azul Noche y Crema.
8. **Responsive**: un único punto de quiebre en `40rem` que ajusta márgenes, menú, formulario, tablas y botón de WhatsApp.

### 9.4 Problema de especificidad (documentado en el CSS)

**Situación:** se quería que el enlace de la página activa se viera naranja, pero la regla general `#menu a` (especificidad 0,1,1) tenía más peso que `.activo` (0,1,0), por lo que el color no se aplicaba.

**Solución:** se aumentó la especificidad de la regla activa a `#menu a.activo` y `nav ul a.activo`.

**Lección:** cuando un estilo "no se aplica", casi siempre otra regla más específica gana. Se revisa en DevTools → pestaña *Styles*, donde las reglas vencidas aparecen tachadas.

## 12. Aprendizajes

1. Una **hoja de estilos única** evita inconsistencias y es más fácil de mantener que un CSS por página.
2. Las **variables CSS** convierten la identidad de marca en un solo punto de cambio.
3. Una regla CSS puede estar correcta y aun así no verse: hay que revisar que el HTML use la clase o el `id` correspondiente.
4. Las **rutas relativas** dependen de la ubicación del archivo que las escribe (`../` para subir de carpeta).
5. Los `id` únicos y los pares `label for` / `id` son indispensables para formularios accesibles.
6. Los mensajes de commit claros (`feat(web): …`) permiten reconstruir esta bitácora.
