# BITÁCORA DEL PROYECTO: RUEDA LIBRE

> Sitio web de alquiler de bicicletas en Medellín y campaña complementaria Rueda Nocturna.

> Este documento registra el proceso de construcción, las decisiones técnicas, los problemas encontrados y los aprendizajes. Los datos que dependen de una prueba manual (tiempos, tamaños descargados, resultados de contraste y pruebas en dispositivos) se dejan pendientes hasta medirlos; no se deben completar con valores inventados.

| Campo | Información |
|---|---|
| Proyecto | Rueda Libre |
| Producto principal | Sitio informativo y de reservas para alquiler de bicicletas |
| Producto complementario | Landing de la campaña Rueda Nocturna |

## 2. Objetivo del proyecto

Construir gradualmente un sitio para que los clientes puedan conocer Rueda Libre, consultar las bicicletas disponibles, revisar las tarifas y los recorridos, y solicitar una reserva.

En la tercera semana se amplía el proyecto con **Rueda Nocturna**, una campaña de recorridos guiados en bicicleta por Medellín durante la noche. Esta campaña se desarrollará con Tailwind CSS y después se integrará con el sitio principal.

## 3. Función de las tecnologías

| Tecnología | Función en Rueda Libre | Ejemplo en el proyecto |
|---|---|---|
| HTML | Organiza el contenido y define la estructura de las páginas. | Encabezados, secciones, tarjetas de bicicletas, tablas y formulario de reservas. |
| CSS | Define la presentación visual del sitio principal. | Colores de marca, tipografías, tarjetas, tablas, menú, espaciados y diseño responsive en `css/styles.css`. |
| JavaScript | Agrega comportamientos interactivos. | Bootstrap lo utiliza para el menú desplegable y el carrusel; `js/reserva-demo.js` y `nocturna/src/formulario.js` muestran confirmaciones locales después de validar los formularios. |
| Bootstrap | Facilita la construcción de interfaces mediante componentes y clases prediseñadas. | Página de pruebas `catalogo-bootstrap.html`, con la cuadrícula de tarjetas de bicicletas. |
| Tailwind CSS | Permite construir la interfaz mediante clases de utilidad directamente en el HTML. | Prototipo inicial de la campaña `Rueda Nocturna` en `nocturna/prototipo.html`. |

# PARTE I. SEMANA 1 — CONSTRUCCIÓN DEL SITIO WEB

## 5. Propósito de la semana 1

Durante esta semana se construyó la base de Rueda Libre. Se pasó de una página HTML inicial a un sitio con tres páginas: inicio, tarifas y rutas, y reservas. Después se trabajaron la semántica, el formulario, la accesibilidad y la identidad visual con CSS.

### Día 1 — Estructura y navegación

#### MiniReto 1. Kilómetro 0: el repositorio y la página base

**Objetivo:** preparar el entorno, crear la estructura inicial del proyecto y entender cómo el navegador solicita una página.

**Trabajo registrado:** se creó el repositorio y la estructura base de Rueda Libre. Se trabajó con `index.html`, carpetas para páginas e imágenes y el archivo de bitácora. La página inicial incorporó la estructura HTML y el título del negocio.

**Conceptos trabajados:** `<!DOCTYPE html>`, `html`, `head`, `meta`, `title`, `body`, `h1`, `p`, Live Server, DevTools, Network y Git.

**Registro de la petición local que aparece en la bitácora anterior:**

| Dato | Valor registrado |
|---|---|
| URL de prueba | `http://127.0.0.1:3000/Rueda-Libre/index.html` |
| Protocolo | `http` |
| Host | `127.0.0.1` |
| Puerto | `3000` |
| Ruta | `/Rueda-Libre/index.html` |
| Método | `GET` |
| Estado del documento | `200 OK` |
| Ruta inexistente | `promociones.html` |
| Estado de la ruta inexistente | `404 – File not found` |

**Aprendizaje:** el navegador realiza una petición al servidor para solicitar el documento. Cuando el recurso existe, el servidor puede responder con estado 200; cuando no existe, puede responder con 404.

#### MiniReto 2. La vitrina de Rueda Libre

**Objetivo:** completar la página de inicio con el contenido del negocio.

**Trabajo registrado:** se agregaron secciones de presentación, información del negocio, servicios, imágenes, listas y enlaces. La página empezó a mostrar la identidad y los servicios de Rueda Libre.

**Aprendizaje:** el contenido debe organizarse con títulos, párrafos, listas, imágenes con texto alternativo y enlaces que permitan recorrer el sitio.

#### MiniReto 3. Tarifas claras: tablas y rutas relativas

**Objetivo:** presentar las tarifas de alquiler y los recorridos mediante tablas, y enlazar páginas ubicadas en carpetas diferentes.

**Trabajo registrado:** se creó `paginas/tarifas.html` con información de tarifas y recorridos. Se utilizaron enlaces relativos entre el inicio y la página de tarifas, además de imágenes desde la carpeta de recursos.

**Datos definidos por el cliente:**

**Aprendizaje:** las rutas relativas dependen de la ubicación del archivo. Desde la raíz se entra a `paginas/`; desde una página dentro de esa carpeta se utiliza `../` para regresar al nivel superior.

#### MiniReto 4. Rueda Libre v0.1: un sitio navegable

**Objetivo:** integrar inicio, tarifas y reservas con una navegación compartida.

**Trabajo registrado:** se creó `paginas/reservas.html`, se incorporó el menú de navegación y se agregó un pie de página con información del negocio y contacto.

**Aprendizaje:** un sitio multipágina necesita rutas correctas desde cada ubicación. El menú debe permitir que el usuario llegue a las demás páginas sin depender del botón Atrás del navegador.

### Día 2 — Semántica y formulario

#### MiniReto 5. Estructura con significado

**Objetivo:** reorganizar las tres páginas con etiquetas semánticas sin perder su contenido ni su navegación.

**Trabajo registrado:** se estructuraron regiones con `header`, `nav`, `main`, `section`, `article`, `aside` y `footer`.

**Aprendizaje:** las etiquetas semánticas describen la función de cada región y mejoran la comprensión del documento por navegadores, buscadores y tecnologías de asistencia.

#### MiniReto 6. El formulario de reservas

**Objetivo:** construir un formulario que recoja los datos necesarios para solicitar el alquiler.

**Trabajo registrado:** se incorporaron campos para datos personales, tipo de bicicleta, cantidad, fecha, plan, comentarios y aceptación de condiciones. Los campos se organizaron en grupos con `fieldset` y `legend`.

**Decisiones de controles:**

| Dato | Control | Motivo |
|---|---|---|
| Nombre | `input type="text"` | Permite escribir el nombre completo. |
| Correo | `input type="email"` | El navegador reconoce el formato de correo. |
| Celular | `input type="tel"` | Está destinado a números telefónicos. |
| Fecha | `input type="date"` | Permite seleccionar una fecha. |
| Tipo de bicicleta | `select` | Permite escoger una opción de una lista. |
| Plan | `radio` | Permite seleccionar una sola opción. |
| Comentarios | `textarea` | Permite escribir un mensaje más extenso. |
| Aceptación | `checkbox` | Permite aceptar o no las condiciones. |

**Aprendizaje:** cada control debe tener una etiqueta asociada y un nombre (`name`) para identificar el dato enviado.

#### MiniReto 7. Reservas sin errores: validación y teclado

**Objetivo:** aplicar las reglas de validación del cliente y revisar la navegación con teclado.

**Reglas solicitadas:** nombre obligatorio con mínimo tres caracteres; documento de seis a diez números; correo válido; celular de diez dígitos que comience por 3; fecha entre el 1 de noviembre y el 31 de diciembre de 2026; bicicleta y plan obligatorios; cantidad entre 1 y 6; comentarios opcionales con máximo 300 caracteres; aceptación obligatoria de políticas.

**Trabajo registrado:** se agregaron atributos de validación nativa como `required`, `minlength`, `maxlength`, `pattern`, `min` y `max`.

**Aprendizaje:** la validación nativa evita que el formulario se envíe cuando los datos no cumplen las reglas definidas. La navegación debe poder realizarse con Tab, Shift + Tab, las flechas y la barra espaciadora.

**Pendiente de revalidación:** la revisión del código actual encontró que el patrón del celular no comprueba exactamente diez dígitos y que hay identificadores repetidos en algunos controles. Consultar la sección 9 antes de considerar el formulario completamente validado.

#### MiniReto 8. Rueda Libre v0.2 en línea: accesibilidad y publicación

**Objetivo:** revisar accesibilidad, contraste de marca y publicación en GitHub Pages.

**Trabajo registrado en la bitácora anterior:** se definió la paleta de cinco colores y se documentaron revisiones de navegación, encabezados, enlaces e imágenes.

| Color de marca | Código | Uso propuesto |
|---|---|---|
| Verde Ruta | `#1E7A4F` | Botones y enlaces |
| Naranja Pedal | `#F39A2B` | Destacados y botones secundarios |

### Día 3 — Identidad visual y CSS

#### MiniReto 9. La identidad de Rueda Libre

**Objetivo:** centralizar los estilos en una hoja externa y utilizar variables para la marca.

**Trabajo registrado:** se creó `css/styles.css`, con variables de color, familias tipográficas y escala de espaciado. La hoja se conectó a las páginas del sitio.

**Aprendizaje:** las variables CSS permiten reutilizar valores y hacer cambios globales desde `:root`. Las fuentes de títulos y párrafos se pueden definir mediante `font-family` y fuentes de respaldo.

#### MiniReto 10. Navegación con estados y sin conflictos

**Objetivo:** aplicar selectores, pseudoclases y resolver conflictos de especificidad.

**Trabajo registrado:** se definieron estilos para enlaces, navegación, botones y campos, incluyendo estados como `:hover` y `:focus-visible`.

**Aprendizaje:** un selector con mayor especificidad puede prevalecer sobre otro. En DevTools se pueden observar las declaraciones que pierden la cascada porque aparecen tachadas.

#### MiniReto 11. Todo en su lugar: modelo de caja

**Objetivo:** controlar dimensiones y espacios de los elementos.

**Trabajo registrado:** se utilizó `box-sizing: border-box`, relleno, bordes, márgenes, anchos máximos y unidades relativas. También se trabajó la presentación de tarjetas, tablas y formulario.

**Aprendizaje:** el modelo de caja permite comprender cómo el contenido, el relleno, el borde y el margen afectan el tamaño final de un elemento.

#### MiniReto 12. Rueda Libre v1.0: lanzamiento

**Objetivo:** consolidar los estilos y aplicar posicionamiento a los últimos componentes.

**Trabajo registrado:** se consolidó la hoja de estilos compartida y se organizaron los componentes visuales del sitio.

**Pendiente de comprobar en el código actual:** la hoja tiene reglas para `.enlace-whatsapp`, pero no se encontró el enlace correspondiente en las páginas HTML revisadas. Por tanto, no se debe registrar el botón flotante como implementado hasta agregarlo y comprobarlo.

**Aprendizaje general de la semana 1:** el sitio se construyó de forma progresiva. Cada reto agregó una parte que después fue utilizada por los siguientes: primero la estructura, luego el contenido y la navegación, después el formulario y la semántica, y finalmente los estilos.

# PARTE II. SEMANA 2 — FLEXBOX, GRID, RESPONSIVE Y BOOTSTRAP

## 6. Propósito de la semana 2

En esta semana se trabajó la distribución del contenido con Flexbox y Grid, la adaptación a diferentes tamaños de pantalla y una primera comparación con Bootstrap.

### Día 1 — MiniReto 1. Un encabezado que se acomoda: Flexbox

**Objetivo:** distribuir el encabezado, el menú y el pie de página en una dimensión.

**Implementación observada:**
- El encabezado utiliza `display: flex`, `justify-content: space-between`, `align-items: center` y `flex-wrap: wrap`.
- La lista del menú utiliza Flexbox y `gap` para separar sus enlaces.
- El pie de página utiliza Flexbox para distribuir sus tres bloques y permitir que bajen de línea cuando el espacio no alcanza.

**Registro de comportamiento que ya estaba en la bitácora:**

| Ancho probado | Encabezado | Pie de página |
|---|---|---|
| 1280 px | Nombre y menú en una fila | Tres bloques en fila |
| 900 px | Nombre y menú en una fila | Tres bloques en fila |
| 500 px | El menú puede bajar de línea | Los bloques se apilan |
| 360 px | El menú puede bajar de línea | Los bloques se apilan |

**Aprendizaje:** Flexbox funciona bien para distribuir elementos en una sola dimensión, como una fila o una columna.

### Día 1 — MiniReto 2. La flota en cuadrícula: Grid

**Objetivo:** mostrar las bicicletas en tarjetas que se acomoden según el espacio disponible.

**Implementación observada:**
- Se agregó la sección `Nuestra flota` en `index.html`.
- Hay siete tarjetas: Urbana Clásica, Urbana Plegable, Montaña Trail, Gravel Aventura, Eléctrica Urbana, Infantil y Tándem.
- `.flota-grid` utiliza `display: grid`, `repeat()`, `auto-fit`, `minmax()` y `gap`.
- Cada tarjeta utiliza Flexbox en columna.
- El enlace de reserva usa `margin-top: auto` para mantenerse al final de la tarjeta.

**Columnas registradas en la bitácora anterior:**

| Ancho | Columnas observadas |
|---|---:|
| 1280 px | 4 |
| 900 px | 3 |
| 500 px | 1 |

**Aprendizaje:** Grid permite distribuir elementos en filas y columnas. Con `auto-fit` y `minmax()` la cuadrícula puede adaptarse a la cantidad de tarjetas sin escribir una media query para cada cantidad.

### Día 1 — MiniReto 3. Layout en dos dimensiones

**Objetivo:** combinar Grid y Flexbox para construir la portada, la galería de rutas y la distribución de reservas.

**Implementación observada:**
- La portada `.portada` tiene una cuadrícula de dos columnas en escritorio.
- La sección de rutas utiliza `.rutas-grid` para distribuir las tarjetas.
- Las tarjetas utilizan Flexbox en columna.

**Estado:** parcial. En la versión revisada no se identifica una distribución completa del formulario y el bloque de contacto en proporción 2:1. Tampoco se identifica claramente una fila de dos campos cortos dentro del formulario, como pide el reto.

**Decisión técnica que se aprende:** Grid se utiliza cuando se necesita organizar contenido en dos dimensiones; Flexbox se utiliza cuando basta distribuirlo en una dimensión.

| Elemento | Herramienta prevista | Justificación |
|---|---|---|
| Portada | Grid | Texto e imagen en dos columnas. |
| Galería de rutas | Grid | Varias tarjetas distribuidas en una cuadrícula. |
| Reservas | Grid | Formulario e información en proporción 2:1. |
| Fila del formulario | Flexbox o Grid | Dos campos cortos en una misma fila. |
| Encabezado | Flexbox | Nombre y menú en una fila. |
| Pie de página | Flexbox | Tres bloques distribuidos en una fila. |

### Día 1 — MiniReto 4. Rueda Libre v1.5: mobile-first

**Objetivo:** adaptar el sitio a celular, tablet y escritorio.

**Implementación observada:** existen reglas para pantallas pequeñas y reglas `min-width` para tablet y escritorio. El código adapta la portada, el encabezado, las tablas y algunos espacios.

**Estado:** parcial respecto al enfoque solicitado. En la hoja actual hay una media query `max-width: 40rem` y reglas `min-width` para el encabezado. El ejercicio solicita que los estilos base sean móviles y que los cambios se agreguen progresivamente con `min-width` en 768 px y 1200 px. Se debe revisar y reorganizar esa parte antes de afirmar que toda la hoja está en mobile-first.

**Tabla de pruebas que debe conservarse y actualizarse después de una nueva revisión:**

| Ancho | Qué se debe comprobar | Resultado |
|---|---|---|

# PARTE III. SEMANA 3 — TAILWIND CSS Y LANZAMIENTO DE RUEDA NOCTURNA

## 7. Semana 3 — Tailwind CSS y campaña Rueda Nocturna

La tercera semana amplía el sitio con una landing para la campaña **Rueda Nocturna**, recorridos guiados por Medellín de jueves a sábado a las 7:30 p. m. La carpeta del proyecto se normalizó a `nocturna/` para respetar las rutas solicitadas y evitar diferencias de mayúsculas en GitHub Pages.

### Día 1 — Sesión 7: introducción a Tailwind CSS

#### MiniReto 1. Prototipo nocturno con Play CDN

**Implementado en:** `nocturna/prototipo.html`.

- Se conserva el prototipo construido con el Play CDN de Tailwind CSS 4.
- Incluye etiqueta de campaña, un único `h1`, subtítulo, los datos “3 rutas” y “Desde $55.000”, y el enlace “Inscríbete”.
- El enlace ahora apunta a `index.html#inscripcion`, que existe en la landing final.
- El estilo está escrito con utilidades de Tailwind; no hay `<style>` ni atributos `style`.

**Comparación del botón con Bootstrap:** en Bootstrap se usan clases de componente como `btn` y `btn-primary`; con Tailwind se combinan utilidades como `bg-*`, `px-*`, `py-*`, `font-bold`, `rounded-*`, `hover:*` y `focus-visible:*`. Bootstrap entrega una apariencia de componente lista; Tailwind permite decidir cada propiedad combinando utilidades.

**Estado de archivos:** implementado. La revisión visual final del prototipo en el navegador queda como comprobación manual.

#### MiniReto 2. Del prototipo al proyecto real: CLI y botones

**Archivos creados:**
- `nocturna/package.json`: dependencias declaradas para `tailwindcss` y `@tailwindcss/cli`, versión 4.1.10.
- `nocturna/.gitignore`: excluye `node_modules/`.
- `nocturna/src/input.css`: importa Tailwind y contiene los tokens de marca y las tres clases de botón.
- `nocturna/src/output.css`: CSS generado para que la landing pueda servirse como archivo estático.
- `nocturna/index.html`: incorpora el hero del prototipo y la campaña completa.

**Comandos utilizados para ejecutar desde `nocturna/`:**

```bash
npm install -D tailwindcss@3 postcss autoprefixer
npx tailwindcss init -p
npm run dev
```
**Botones implementados:** `btn-primary`, `btn-secondary` y `btn-outline`. Los tres incluyen estilos `hover:` y foco visible con utilidades `focus-visible:ring-*`. El CSS fuente tiene exactamente tres reglas con `@apply`, dentro de `@layer components`.

**Comprobación de generación:** se encontraron utilidades utilizadas en `src/output.css`, por ejemplo `bg-azul-noche` y `grid-cols-1`. La clase de prueba `bg-pink-500`, que no se utiliza en las páginas de la campaña, no se genera. El archivo no incluye `node_modules`.

#### MiniReto 8. Código legible y veredicto: Bootstrap vs Tailwind

Las clases de los botones se centralizaron en tres componentes `@apply`; las cards mantienen su marcado utilitario y comparten sus clases visuales. Se ordenaron las utilidades por layout, espaciado, tipografía, color y estados.

**Medición local del archivo:** `nocturna/src/output.css` pesa **25.384 bytes** (25,4 kB decimales). Es el archivo generado y entregado dentro del ZIP. La medición de CSS y JavaScript de Bootstrap debe completarse en DevTools → Network, porque el tamaño transferido depende de la descarga y compresión del recurso CDN y no se obtuvo una captura verificable en este entorno.

| Criterio | Bootstrap | Tailwind CSS |
|---|---|---|
| Curva de aprendizaje | La grilla y componentes dan una estructura rápida al comenzar. | Requiere aprender y combinar nombres de utilidades; la CLI agrega el paso de compilación. |
| Personalización | Se adapta mediante variables y CSS complementario; parte de patrones predefinidos. | El marcado permite controlar cada propiedad de forma directa y definir tokens con `@theme`. |
| Tamaño final | Falta medir CSS y JS descargados en Network. | `output.css` local: 25.384 bytes; falta confirmar la salida definitiva de `npm run build --minify` en el equipo. |
| Casos de uso | Catálogos y sitios que aprovechan componentes y grillas prediseñadas. | Landing de campaña con un sistema visual muy particular y utilidades precisas. |

**Recomendación provisional:** mantener Bootstrap para los componentes de navegación y carrusel que se integraron al sitio principal, y utilizar Tailwind en la landing Rueda Nocturna. No se recomienda migrar todo el sitio solamente por esta campaña. La recomendación debe revisarse cuando se mida Bootstrap en Network y se confirme la compilación CLI local.

**Estado:** refactorización y medición de output.css implementadas; comparativa de tamaños reales de Bootstrap pendiente.
